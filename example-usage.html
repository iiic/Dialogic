Dialogic v 0.2

Dialog element javascript working like native Notification

Just vanilla javascript, no jQuery or other libraries. Styles and examples included in repo. Same parameters as browser's default Notification() function

Differences between Dialogic and Notification

  • Dialogic does not have the permission property, you can show a popup at any time without having to obtain permission
  • Dialogic has the option requireInteraction: true by default (can be changed), so popups are not hidden automatically, unlike Notification, which has requireInteraction: false by default (this can also be changed when creating a Notification instance)
  • Dialogic does not implement these properties yet:
    • actions
    • badge

Two consecutive function calls… what will happen?

	new Dialogic( 'title', {

		icon: 'img/crow.png'
	} );
	new Dialogic( 'another title', {
		body: 'and a shorter text'
	} );

Notification: 
<script>
	new Notification( 'title', {
		body: 'Longer content that better describes what it is actually about. Plus some more text…',
		icon: 'img/crow.png'
	} );
	new Notification( 'another title', {
		body: 'and a shorter text'
	} );
</script>
Same behavior in both cases. Both notifications and dialogs are queued and displayed once per given time interval (for Dialogic it is 50ms (the value can be changed in the global settings), for Notification I don't know, my estimate is about 250ms). In both cases the order is from the newest to the oldest. So in the example above, from the bottom up.

Using a tag to display a notification/popup only once /// @todo : finish, overwriting the old content with the new one is missing here

Dialogic, a dialog with a tag is not displayed again until the page is reloaded. When called repeatedly with the same tag, a 2nd dialog is not displayed, only the content of the first one changes. Same as with Notification, the default value of renotify is false, so there is no display effect, just a quiet and unobtrusive replacement of the content with the new one. 
<script>
	new Dialogic( 'dialog with tag', {
		tag: 'some-id-text-or-number',
	} );
	setTimeout(function() {
		new Dialogic( 'another dialog with the same tag', {
			icon: 'img/crow.png',
			tag: 'some-id-text-or-number',
		} );
	}, "3000");
</script>
(Calling Dialogic repeatedly will never display the dialog again, because there is no notification center here that would allow removing the popup from the displayed ones, as with notifications.)
Notification, if the message has a tag (and the renotify option set to false, which is the default) and is called multiple times, the behavior depends on the notification center of your OS. Unless you delete the message from it, it will not be displayed a second time, but the second call can still change the content of the notification (if it is called again with different text content but the same tag): 
<script>
	new Notification( 'notification with tag', {
		tag: 'some-id-text-or-number'
	} );
	setTimeout( function () {
		new Notification( 'another notification with the same tag', {
			icon: 'img/crow.png',
			tag: 'some-id-text-or-number',
		} );
	}, "3000" );
</script>
(Calling Notification repeatedly will not display the message again until you remove it from the notification center. So there is a way to display the notification again.)

Using tag and renotify together /// @todo : finish, overwriting the old notification content with the new content is missing here

In both cases, I display a notification/dialog and then cover it with another one 3s later. The difference from the previous example is the use of renotify: true, which makes it display again, including the effect.

Dialogic: 
<script>
	new Dialogic( 'dialog with tag', {
		tag: 42,
	} );
	setTimeout(function() {
		new Dialogic( 'another dialog with the same tag', {
			icon: 'img/crow.png',
			tag: 42,
			renotify: true,
		} );
	}, "3000");
</script>
Notification Because of the effect, it might seem that these are 2 independent notifications one after another, but in the notification center you will find that there is only one. And if you press the button to run the code again, at first nothing happens (because of the same tag, and the 1st notification doesn't have renotify) and after 3s the notification is displayed (because the 2nd notification in order does have renotify): 
<script>
	new Notification( 'first', {
		tag: 42,
		requireInteraction: false
	} );
	setTimeout( function () {
		new Notification( 'second', {
			tag: 42,
			renotify: false,
			requireInteraction: false
		} );
	}, "1000" );
	setTimeout( function () {
		new Notification( 'last', {
			tag: 42,
			renotify: true,
			requireInteraction: false
		} );
	}, "2000" );
</script>

Summary of using tag and renotify

This may be a bit harder to understand, so I also describe it here in bullet points. The behavior is exactly the same in both cases, I use the collective term "message" for both the notification and the dialog.

  • has (the same) tag, does NOT have renotify:
    • the message is still displayed, i.e. the user has not hidden the notification/dialog yet, nor has it been hidden automatically after some time: The new message overwrites the content of the original one, without any (sound or visual) effect of displaying a new message.
    • the message has already been hidden, in that case the new message is not displayed anymore. With Dialogic never again (unless the page has been reloaded in the meantime), with Notification it can only be displayed if the previous notification with the same tag has already been deleted from the notification center.
  • has (the same) tag, and has renotify: true:
    • the message is still displayed, the second message overwrites the content of the first one with the effects of a new display (both sound and visual). With Notification, the notification center shows it as 1 notification, not as two. That is the difference compared to sending 2 independent notifications.
    • the message has already been hidden, in that case the new message is displayed again, just as if it were independent (with a different tag). With a notification, it overwrites the older notification with the same tag in the notification center.

Automatic hiding of notifications… options

Dialogic, by default popups are not hidden (requireInteraction = true), this example shows, for a change, how popups can be hidden automatically with (requireInteraction = false) after 6s (which is the default time, it can be changed using the global settings shown in the example below): 
<script>
	new Dialogic( 'title', {
		body: 'this popup will close by itself after 6s',
		requireInteraction: false
	} );
</script>
Notification, by default hides notifications after 6s, in this piece of code I set that I never want the notification to be hidden: 
<script>
	new Notification( 'title', {
		body: 'this notification never disappears by itself, it requires a click',
		requireInteraction: true
	} );
</script>

Attached events

Dialogic: 
<script>
	let d = new Dialogic( 'title', { body: 'events are attached to this dialog… alerts' } );
	d.addEventListener( 'click', () => { alert( 'event click' ); } );
	d.addEventListener( 'close', () => { alert( 'event close' ); } );
	d.addEventListener( 'error', () => { alert( 'event error' ); } );
	d.addEventListener( 'show', () => { alert( 'event show' ); } );
	// alternatively it can be written as (and it will work the same way):
	// d.onclick = () => { alert( 'event click' ); };
	// d.onclose = () => { alert( 'event close' ); };
	// d.onerror = () => { alert( 'event error' ); };
	// d.onshow = () => { alert( 'event show' ); };
</script>
Notification (important: there is often a misunderstanding about when the close event is fired. It is not fired when the notification is hidden from the notification center, but only after clicking "close", which only notifications with requireInteraction = true have. So requireInteraction = true is the only way to fire the close event): 
<script>
	let n = new Notification( 'title', {
		body: 'events are attached to this notification… alerts',
		requireInteraction: true
	} );
	n.addEventListener( 'click', () => { alert( 'event click' ); } );
	n.addEventListener( 'close', () => { alert( 'event close' ); } );
	n.addEventListener( 'error', () => { alert( 'event error' ); } );
	n.addEventListener( 'show', () => { alert( 'event show' ); } );
	// alternatively it can be written as (and it will work the same way):
	// n.onclick = () => { alert( 'event click' ); };
	// n.onclose = () => { alert( 'event close' ); };
	// n.onerror = () => { alert( 'event error' ); };
	// n.onshow = () => { alert( 'event show' ); };
</script>

Timestamp… option to add a time in the future or in the past

Same behavior in both cases. The date and time is printed with the given object (dialog / notification), for a dialog in the bottom left corner, for a notification in the notification center. However, this property is not meant for delayed display, both the notification and the dialog are always displayed immediately, the set time is just information for the user.

Dialogic: 
<script>
	const plus30min = Math.floor( new Date(Date.now() + 30 + 60 * 1000) );
	new Dialogic( 'title', {
		body: 'This dialog is displayed immediately and shows a time one minute later than the current one.',
		timestamp: plus30min
	} );
</script>
Notification: 
<script>
	const yesterday = Math.floor( new Date(Date.now() - 24 * 60 * 60 * 1000) );
	new Notification( 'yesterday', {
		body: 'this notification pretends to be from yesterday',
		timestamp: yesterday
	} );
</script>
